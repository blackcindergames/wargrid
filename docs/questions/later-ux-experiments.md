# Later: UX experiments

Parked interaction ideas from the visual and UX proposal review ([design answers](../reference/design-answers-2026-11-08.md#visual-and-ux-proposal-review-user-2026-11-15)). None is planned. Each waits for its prerequisite, then gets a small prototype against today's interface; adopt it only if it beats that baseline on a real task.

| Idea | What it would do | Waits for | Keep it only if |
|---|---|---|---|
| Consequence preview | Hovered cell and armed placement show more refusal causes than credits and power (placement, prerequisites) | P2.3b forecast card, a read-only reason query on the simulation interface | purchase outcomes are predicted better without slower placement |
| Grouped alerts | Nearby repeated alerts merge into one group with a count and one edge arrow; click jumps, selection unchanged | alert feed (M7.6), fog of war (M7.9) | fewer missed attacks, no more false jumps, last-known positions never follow unseen attackers |
| Selection lens | Hovering a per-kind row highlights its members; after filtering, one restore of the previous selection ("120 → 12 Bulldozers") | P2.3a and P2.3b | fewer wrong orders on mixed groups, experts no slower |
| Production workload | Production strip marks each factory producing, empty, power-limited or blocked, only where the simulation exposes that state | production strip (M7.6) | stalls found with fewer factory inspections, no invented reasons |
| Order intent | Selected units briefly show their submitted target and whether the order was accepted; routes only from real route data | P5 and P6 | failed orders diagnosed better without permanent route lines |

Rejected for the current roadmap (user, 2026-11-15): a cursor command wheel (conflicts with P3's right-drag pan and the fixed grid's muscle memory) and formation-shaped drag (promises slot assignment P5 and P6 cannot honour through chokes).
