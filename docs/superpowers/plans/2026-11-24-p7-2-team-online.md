## Why and what the player notices

You and a friend (two online clients) play one team against two bots the host's game runs. The host picks the map (only maps with four or more starts) and both bot factions; teammates start side by side, draw in two blues, the bots in red and orange; a right-click on your teammate's unit moves there instead of a refused attack. Leaves end the match with one plain line; a defeated guest may leave and the host plays on. Refuting observation: the friend's client ends the match with "bad command stamp" on the first bot order, or the two clients' digests differ. First playable slice: T2-1 to T2-7; the owner plays it, then T2-8 (pings) and T2-9 (docs, card, gate).

**Out:** allied bot and S3 ally riders (`PK` Later item 9), P8 reconnect and leave reasons, ready step, start countdown (P11), artillery standoff, tech escalation, bot levels, any relay or protocol change.

## Design (fixed)

- **Seats.** Sim players 1 (host) and 2 (guest) on team 1, bots 3 and 4 on team 2; two relay and lockstep seats. `MatchSettings.for_map(id, bots)` adds `bots: [{player, faction}]` to the opaque `start` settings only when there are bots (1v1 hello unchanged; relay limit 4096 bytes, `relay/envelope.go:13`). Bot players are exactly `seats + 1 ..` in order. `MatchSettings.teams(seats, bot_count)`: no bots `[1 .. seats]` (today), else humans 1 and bots 2. `starts(id, seed, teams)` (`match_settings.gd:30-36`) already places teammates side by side through `StartSpots.assign`; SS7 needs no re-pin.
- **Lockstep allowed sets.** `Lockstep._init` (`net/lockstep.gd:40-52`) gains `allowed: Dictionary` (seat → players; default each seat itself); `for_start` (`:54-57`) derives it from `message.settings.bots`: seat 1 gets every bot. `_receive_tick`'s stamp loop (`:265-268`) tests `_allowed[s].has(command.get("player"))` (guarded as today: `Wire.decode` lets the field be absent) and keeps the tick check. `submit(payload, player := 0)` (`:66-77`): 0 means `_seat`; a player outside `_allowed[_seat]` returns false and queues nothing. One rising `_sequence` for all of a seat's players (the sim checks per-player rise only, `simulation.gd:247`; recorded as a deviation from `OT:51` in T2-9). `record` (`:137-145`) erases `_submit_times` for every player in `_allowed[_seat]`, appends to `_latency` and `_rejections` only for `command.player == _seat`, and puts bot refusals into `bot_rejections()` (read by tests only), so the host never sees, hears or times an order it did not give (review P1-2; today's leak path `online_driver.gd:194-209`, `match_screen.gd:233-243`). `_defeated` (`:301-302`) tests every player of `_allowed[s]`, so a defeated host's leave ends the match while a bot lives (review P1-1). `bots()` (every allowed non-seat player, same on both clients) and `allowed(seat)` are read-only. `opponent_left()` (`:207-208`) adds `bots().is_empty()`: in a 2v2 the other seat is a teammate.
- **Issue-time validation.** New read-only `Simulation.check_command(command) -> String`: `"Match ended"` when over, else `_validate(command)` (`simulation.gd:240`), empty when `issue_command` would accept. Its only side effect is the one `issue_command` already has: a build preview may bump the unhashed `navigation_builds()` counter (`construction.gd:91`); it never changes `tick_hash()` or the digest. `SeatSim.issue_command` (`net/seat_sim.gd:18-20`) returns its error before `submit(command, command.player)` (known bug b, `docs/reference/p7-verification.md:487`).

## Run rules (every task)

- Handoff run rules apply (no `ask`-rule commands, no windows, questions by notification and ledger ruling, stops never ruled on).
- **Setup:** `mkdir -p build` once in the worktree (git-ignored, absent at the base).
- **Red first:** each task's named tests fail for the stated reason before implementation; a parse or load error is not red, so new members first go in bare and behaviour-neutral (the old behaviour, or an empty stub) and the suite loads. Tests marked *guard* hold at the base already (an existing protection or a default that must not move); they are shown green, not red. New tests use the [simulation interface](../../reference/sim-interface.md) (`tools/test_sim_boundary.py`); bot memory through `Skirmish.team_memory` (`skirmish.gd:49-50`), never `Skirmish._bot`.
- **Iterate:** `WARGRID_TEST_ONLY=<suite or case> sh tools/run_tests.sh > build/t.log 2>&1; echo "exit=$?"` (timeout 600000; `rg -n 'FAIL:|CASES|SCRIPT ERROR' build/t.log`).
- **Task end:** full suite `sh tools/run_tests.sh > build/suite-T2-n.log 2>&1; echo "exit=$?"` (`TESTS PASSED`), `sh tools/run_lint.sh`, `sh tools/run_warnings.sh`, plus the task's extra checks; `sh tools/check_public.sh` before the commit.
- **Expectation rule:** a task changes only the existing expectations listed under it (and the helpers it names). Any other existing check that moves is a stop: park, never widen.
- **Review:** each task gets one fresh Opus (high) review (diff, this plan's task and "Same-tick cases"; per new test, the production change that kills it) and one fix round; then the coordinator commits. Player-experience pass once over the whole branch after the owner's match.
- `game/scripts/match/sim_pump.gd` and `online_driver.gd` collide with SB5a's planned night work; note an SB5a branch in the ledger if one appears.
