## Decided for you

1. **[proposed] Two targets, fail-safe default.** `web/sws.toml` stays as it is (production, no isolation headers). A new `web/sws-threads.toml` copies it and adds both isolation headers. The final Docker stage gets `ARG SWS_CONFIG=sws.toml` and `COPY ${SWS_CONFIG} /sws.toml`, so a missing build arg ships production’s policy. Test selects `Web Threads` + `sws-threads.toml`; production, tag releases and the test rollback select `Web` + the default. No extra Fly app or tag artifact. This departs from the spec’s literal “COOP/COEP in `web/sws.toml`” only in the file name.
2. **[proposed] Smallest fallback.** Record the stock diagnostic and the outcome of “Open in browser” on the same invite URL. Defer a fallback page and service worker. A playable HTML fallback would have to select between “two separate builds” before engine startup. [Emscripten pthreads](https://emscripten.org/docs/porting/pthreads.html#compiling-with-pthreads-enabled)
3. **[proposed] One preference.** A new reader `game/scripts/presentation/sim_settings.gd`, like `graphics_settings.gd`, stores a boolean in `[simulation]` on `AudioSettings.path` (the runner already isolates and deletes that file per case). Default off; no in-memory fallback, like the other readers. The row and the stored-bool request apply only where `OS.has_feature("web") and OS.has_feature("threads")`; no custom feature tag (the only test tag, `wargrid_tests`, switches the main loop to the test runner, `project.godot:12`). Native keeps SB5a’s switch, the production `Web` preset ignores a saved true, and an SB6 GO needs no preset edit. Launcher Settings stays untouched: the `threads` guard and frame-polled start mean a stored on can no longer hang a match.
4. **[proposed] Pools and audio.** Write `threads/emscripten_pool_size=8` and `threads/godot_pool_size=4` explicitly into `Web Threads`. Leave headroom for audio and the sim thread. Keep current Web audio settings. Poll worker readiness across main frames because an unpooled pthread “will only run after you return to the event loop.” [Godot pool settings](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/doc_classes/EditorExportPlatformWeb.xml#L81-L88) · [Emscripten startup](https://emscripten.org/docs/porting/pthreads.html#special-considerations)

## Same-tick and ordering cases

Toggle while a note is pending, including online while ticks keep stepping under the open menu, then resume. The original pump drains in order and retains its mode. On offline Restart and online rematch, stop the old pump before reading the preference for the new one. A failed worker’s latch still wins, and reopening Settings after it shows the stored preference without clearing the latch. An online peer keeps its own mode and command stream.
