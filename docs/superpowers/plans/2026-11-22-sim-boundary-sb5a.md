**Goal:** `SimPump` can run every job on one worker thread, native and headless, switched on by `WARGRID_SIM_THREAD=1`, off by default. With the switch off nothing changes. With it on: digests are equal to inline on four loads, the scene suite is green with every scene pump in worker mode, a fault ends the match within 5 s, and a loopback online match with one worker client plays to its end with equal hashes.

**Architecture:** One code path; the inline pump stays the reference. `post` accepts a job (responsibility for that tick passes to the pump at that instant) only when there is room. The worker runs the same `run_job` outside the lock and publishes the note and a fresh slot under the lock. `drain` takes them under the same lock. `query` waits for its own reply with a deadline. A worker-side failure travels as a marker in the queue and becomes one main-side `failure()` reason. Drivers ask for room before they build a job or take a lockstep tick.

**Tech stack:** Godot 4.7.2 typed GDScript (`Thread`, `Mutex`, `Semaphore`, `Logger`), suite runner `game/tests/run_tests.gd` with `tools/run_tests.sh`, Python checks under `tools/`, POSIX sh tools. `relay/`, `protocol/` and `game/scripts/simulation/` untouched.

Queries are not counted (the caller blocks, so at most one exists) and never enter the drain queue. The spec left this open (API block); critique question 6 asked SB6 to measure caps 1 and 2.

- **Why 3 (model, private, `~/projects/wargrid-overnight-work/sb5a/queue-model/`):** a trace-driven model on the recorded Deck job percentiles (spike 2026-11-15, follow-up 2026-11-20). At Deck cadence (about 90 fps) caps 2 and 3 are indistinguishable (0 ms visible extra; at most 0.07 % of posts reach depth 3). With a 150 ms hitch every 10 s, cap 2 adds up to about 20 ms visible delay and cap 3 none. Reference engines bound catch-up per frame, not a worker queue: Recoil by a time budget (`rts/Net/NetCommands.cpp:245-256`, `a0240a9b5c`), 0 A.D. "stop fast forwarding after 2 turn lengths" (`source/simulation2/system/TurnManager.cpp:79-84`, `136720dada`). The spike's `backlog_max` 2 was its own cap (`MAX_QUEUED = 2`, `worker_driver.gd:16,161-164` on `spike-worker-threads` `713adcc4`), and with room before `take` a refusal no longer ends an online match.
- **What would refute it (SB6):** more than about 1 % of posts on the Deck seeing 3 unpublished jobs, or a visible result age p95 clearly worse than at cap 2. Then the cap drops to 2 and the job tail is shortened instead. So SB6 records the refused count, the longest refusal streak, the maximum depth reached and `age_ms`, not only `backlog_max` (Task 12's `WORKER RUN` line carries them).

- **Accepted, unfinished ticks:** at most 3 (one executing plus two waiting). If only waiting jobs counted, it would be 4; the plan does not use that rule.
- **Pace floor (known limit, beside the catch-up bound):** an estimate, not a ceiling: publishing frees room before drain, so further physics steps in the same render frame can post again, and three accepted jobs may still wait for a worker that has not begun the first. Roughly min(30, 5 × fps, `MAX_QUEUED` × fps) ticks/s, so with the worker game time may slow below about 10-12 rendered fps at cap 3 (cap 2: about 15-17 fps); inline today slows below about 6 fps with a cheap simulation. Task 10 measures it; it is not a stop.
- **Completed, undrained notes** are counted separately: publishing frees capacity before the main thread drains, so further physics steps in the same render frame can post again. The bound is posts per render frame: online `CATCH_UP_STEPS` (2) × physics steps per render frame (engine default at most 8) = 16; offline 8. That is the driver's ceiling; online, the lockstep's own bound of input delay + 1 = 5 ticks per rendered frame (accepted, Task 10) is lower. `drain` empties them every `_process`. Task 3 tests the bound with a frame script.

**Single producer:** only the main thread calls `post`, `query`, `stop`, `has_room`, `drain`. The worker only decreases the unpublished count (publishing) or sets a failure marker. So between `has_room()` true and `post`, room can only grow. The one race is a terminal failure, handled in step 2.

**Healthy trace** (online, input delay D, ticks N to N+3):

1. The worker is running N; N+1 and N+2 are waiting; unpublished = 3. Packets for N+3 arrive. Main's `step()` polls the transport, `Lockstep.receive` buffers them, the catch-up loop reads `pump.has_room()` → false and breaks **before** `take(N+3)`. Bookkeeping unchanged: `_next_tick == N+3`, `_taken == [N, N+1, N+2]`, the credit earned before the loop (`online_driver.gd:113`) kept and none spent (spending follows a successful `take`, `:118`), `pump.failure() == ""`, lockstep status still `running`, the lockstep still holds N+3's packets. The loop also breaks before `take` when `pump.failure()` is set, so a failed pump (which reports room, Decided 7) never consumes a tick and its own reason, not a later leave or hash end, ends the match. **Precedence [proposed]:** the lockstep keeps its first end (`set_relay_lost` and `set_protocol_error` return once ended, `net/lockstep.gd:196-202`), and `step()` polls the transport and may set relay lost before the loop (`online_driver.gd:111-112`); so a relay loss seen before the pump failure stays the reason, a pump failure seen first stays its own, and either way the transport closes in that frame. Tests: `test_sb5a_full_pump_leaves_next_tick_in_lockstep`, `test_sb5a_relay_loss_and_pump_failure_same_frame` (both orders).
2. The worker finishes N. Under the lock, in this order: append N's note, set READY to N's slot, unpublished -= 1. Unlock. In one critical section it checks the quit flag and takes N+1 (N+1 was already counted); an empty queue with quit set exits, an empty queue without quit waits on the semaphore again. It runs N+1 outside the lock. N's note is readable by main from the unlock, and main reads it only at its next `drain`. The next `step()` sees room, calls `take(N+3)`, posts it, unpublished = 3. If the worker failed between `has_room()` and `post` (marker queued), `post` refuses. Main then reads the marker inside `post`, sets the pump's first failure reason itself, and returns false. The online driver ends the lockstep with `sim pump failed: <reason>`, not "sim pump refused tick", and closes the transport. N+3's packets are consumed, but the match is over anyway.
3. A render frame drains N and N+1 together: `_finish_job` pops `_taken` front-first, checks `note.tick == taken + 1` (N+1, then N+2), records each note's own `issued`, and calls `finish_tick` with that note's own snapshot and digest (computed inside that job). The existing end exceptions are unchanged: a note past the end with no tick movement records nothing (`online_driver.gd:150`), and a note between taken ticks whose tick is not the taken one + 1 is a protocol end (`:151-154`; `test_sb4_foreign_note_ends_match`, `test_online_scene.gd:2067`). With `_taken` empty (`:147`) a same-tick note stays harmless, as a test publish is (`test_sb4_publish_is_not_a_tick`, `:1986`: records and sends nothing); a note that advanced past `_last.tick` with nothing taken is unexplained and ends the match before anything is recorded, submitted or sent (`test_sb5a_pairing_rejects_foreign_note`). Catch-up stays at 2 ticks per physics frame with credit 4 (`:10-11`, unchanged), and stays bounded at input delay + 1 = 5 ticks per rendered frame, because own packets are sent from `drain` (accepted limit, measured, not fixed **[owner, 2026-11-22]**; Task 10; `test_sb4_three_callbacks_one_drain`, `:1969`, already pins five takes across three callbacks before one drain). Every accepted tick job carries the standing preview request (P2.3b's F33); when room runs out no job is built, so nothing is lost and the next frame's first job carries it. A pending build is cleared by its answer as today. Test: `test_sb5a_two_notes_one_frame_pair_in_order`.
4. **Leave before drain.** `leave()` ends the lockstep and closes the transport; `close_match` calls `driver.stop()` → `pump.stop()`. N, the running job, finishes and publishes; the worker re-checks quit after every job (spec: "join, at most one job"), so it exits before N+1. `stop()` drops N+1 and N+2 and subtracts the two jobs it dropped; N's own publish brings the count to 0. Main waits for the exit acknowledgement (bounded, see "Thread lifecycle") and joins. `keep_match` then calls `record()`. After a join the pump's owner is main again, so the record's query runs inline on the caller and returns the digest of the jobs that ran (through N). Online the saved playtest record has two sources (`match_screen.gd:211-229`): its command lines come from `driver.match_log()`, which is `Lockstep.command_log()` (`online_driver.gd:269-270`), filled only by `_finish_job`'s `record`, and its end tick and digest from `driver.record()`, which is `pump.record()` (`:170-171`). So a job that ran but was not drained would change the digest while its issued commands are missing from the saved log. **[proposed]** Online `stop()` therefore takes the stopped pump's completed notes and passes each through the pairing guard and `_lockstep.record` only (no bot submit, no `finish_tick`, nothing sent after the leave), so log and digest meet at N and replaying the saved record gives its end digest. The commands of N+1 and N+2 are lost with the leave, as the player left. Test: `test_sb5a_leave_record_replays` (a completed, command-bearing, undrained job and a running one at the leave; the saved playtest record replays to its end tick and digest).
5. **Restart or rematch with jobs undrained.** Both drivers' `create` now stop the old pump **before** `Skirmish.create` builds the new simulation (today `adopt` stops it after, `offline_driver.gd:36-41`, `online_driver.gd:64-76`). So an old worker never runs beside the new match's cache warm-up, or a test's `clear_test_kinds`. The driver's only reference is the new pump. The old pump's notes, and any late result, sit in the old object, which no driver or screen can reach. Tests: `test_sb5a_restart_drops_old_notes`, `test_sb5a_create_stops_old_pump_first`. Both `adopt`s read `first_note.tick` at once (`online_driver.gd:79-81`, `offline_driver.gd:44-46`), so `start()` never returns null: a null job zero fails the pump (`_fail("start")`, the null-result cause) and returns an empty note at the simulation's tick, and the freeze card or online start end follows (`test_sb5a_job_zero_null_fails_pump`).

**Stalled trace** (N runs past the stall limit):

1. N is running and N+1 and N+2 are waiting. The stall clock (F frames, T milliseconds) was set at the `post` that took the unpublished count from 0 to 1, and is set again at every `drain` that took at least one note while the count stays above 0; it is checked only while the count is above 0 and no failure is set (Decided 2). So an idle pump, the offline pause menu and an online wait for a slow peer can never trip it. Each `drain` first takes any published notes; a note that arrived counts, even if it was finished while the app was suspended. When **both** frames ≥ F + `STALL_FRAMES` (90, 3 s at 30 Hz) and wall time ≥ T + `STALL_MSEC` (3000) hold, main sets `failure() = "stall: job at tick N ran over 90 frames"`. Requiring both means a suspend (wall time jumps, frames stop) and a burst of catch-up frames each cannot trip it alone. Main then calls `_abandon(cause)` (see "Lifetime of a failed pump"). Offline: the freeze card shows (`FREEZE_NOTICE`). Online: the lockstep ends with `sim pump failed: stall`, the transport closes in the same frame, and the peer sees "Your opponent left" with no result recorded **[owner, 2026-11-18]**.
2. A leave during the stall, before the stall limit: `stop()` waits up to `WAIT_MSEC` (5000 ms) for the exit acknowledgement, does not get it, calls `_abandon("stall: stop waited 5000 ms")` and never calls `wait_to_finish()`. A `stop()` on a pump that is already abandoned (stall found by `drain`, `query` or the start handshake) returns at once. `record()` on a pump whose thread is still alive returns the last shown tick and view, an empty log, `digest ""`; the end text comes from `failure()`.
3. A new match after the stall runs inline (latch). If N ever returns, the worker publishes into the abandoned pump, sees quit, and exits. It never takes N+1.

## Ownership

| Method | Caller | Owns while running | Lock | Can wait for |
|---|---|---|---|---|
| `post(job)` | main only | the job until it is appended; from the unlock on, the job belongs to the worker | queue mutex, to append and count | nothing |
| `run_job` (static, via `_run_owned`) | the owner thread: main inline, before spawn and after a join; the worker in between | the simulation, the recorder, the job, the new note and slot | none: never under the queue lock | nothing |
| worker loop | the worker | nothing between jobs | the queue mutex to take a job, and again to publish | the work semaphore |
| `drain()` | main only | the taken notes and slots from the unlock on; never written again by anyone | queue mutex, to take notes, swap slots, read markers | nothing |
| `query(job)` | main only | nothing; the job goes to the worker at the unlock | queue mutex to append; the reply is read under it | its reply semaphore, as a `try_wait` poll with a `WAIT_MSEC` deadline; returns null at once on a failed pump; runs inline after a join |
| `record()` | main only | nothing | as `query` | as `query` |
| `stop()` | main only | the thread object, until it joins or abandons it; waiting jobs are dropped | queue mutex, to set quit, drop the waiting jobs and subtract them from the count | the exit acknowledgement for at most the running job, polled up to `WAIT_MSEC` |
| `live()` | main, tests and setup only | the simulation, but only while the pump is inline, or worker and idle and not abandoned, or after a join | none | nothing; debug `assert(not busy() and not abandoned())`: a failed pump reports not busy, so `busy()` alone would let a reader touch a simulation an abandoned worker still runs |
| `has_room()`, `busy()` | main only | nothing | queue mutex (they read the unpublished count) | nothing |

- **A note becomes readable** at the publish unlock, and main reads it only through `drain` or a query reply. A query's reply never touches READY, `current()` or `previous()` (its slot is null), so `record()` or the desync query followed by `drain` keeps the shown slot.
- **Pure data across threads:** `Job`, `Note` and `Slot` hold only `int`, `bool`, `String`, `Dictionary`, `Array` and packed arrays. They hold no `Node`, `Resource`, `Callable` or `Signal`, because whichever thread drops the last reference runs the destructor. A static check enforces the declarations (Task 3); the nested payloads it cannot see are known and stay: `view.units` is a fresh `ViewRows extends RefCounted` per job holding only packed columns, `container` included (`simulation.gd:831`, `view_rows.gd:21`); a standing preview holds a `Vector2i` origin (`orders.gd:538-544`); a shot's `target_building` is that job's copied building row (`_attach_targets`, `sim_pump.gd:146-150`), which sound reads after drain. Views are compared by a value projection (`held_copy`, `test_view_rows.gd:270-277`, every column); `StateHash.digest` hashes `state.entities` (`state_hash.gd:10-24`), so it is for snapshots only.
- **Owner thread [owner, 2026-11-18]:** the pump keeps `_owner_id`, which is the main id until spawn. The worker writes its id at loop entry and posts a start semaphore; `start()` waits for it (bounded) and stores the id. After a successful join `_owner_id` is main again. `_run_owned` compares `OS.get_thread_caller_id()` with `_owner_id` in every build. A mismatch calls `push_error`, fails the pump (`owner thread`) and publishes a failure marker. GDScript has no `final`, so `tools/test_sim_boundary.py` fails if any file but `sim_pump.gd` defines `_run_owned`; the test seam `_note_for` sits inside it, so `failing_pump.gd` cannot bypass the check.
- **Profiler [proposed]:** the Profiler (`debug/profiler.gd`, six statics, `Time.get_ticks_usec()` when enabled) is reachable from `run_job` and not thread-safe. In worker mode `start()` calls `assert(not Profiler.enabled)` (debug), and nothing enables it while a worker lives (Task 12 drops the bench patch's later enable). The ten Profiler cases run with inline pumps under the switch (Allowed test edits 2). No mutex.
- **The worker never waits on the main thread**, apart from the test gate's bounded `try_wait`. That is what keeps main's polls in `query`, `stop` and the start handshake free of deadlock. The worker calls no `OS.has_feature` (it writes an unlocked cache, and is proxied to the browser's main thread on Web) and no `print`/`printerr` (a synchronous write to the browser main thread on Web); the mode and the logger are set up on main before `Thread.start`. **[Godot 4.7.2 source, read 2026-11-22]** So an `OS.*` call reachable from `run_job` is a stop, except `OS.get_thread_caller_id()` (lock-free, used by `_run_owned` and `PumpLogger`) (Task 1 follows the call graph from `run_job`, not only `game/scripts/simulation/`: at `608267eb` the simulation has no `OS.*` call; `FileAccess.open` in `map_data.gd:8-13` is reached only through `Skirmish._default_map()` behind an empty-cache check (`skirmish.gd:74-76`), which `start()` warms on main first (`sim_pump.gd:138-143`); the transitive profiler is above).
- **Debug invariants [proposed]:** at each lock exit, debug builds assert 0 ≤ unpublished ≤ the effective cap (`MAX_QUEUED`, or `cap_for_test`'s cap), notes in tick order, and READY's tick equal to the last appended note's tick (Lamport-style; the plan's "room can only grow" is that proof's step).
- **Two pumps at once:** while an old abandoned worker or a test's second pump runs beside the main thread, these are the nine simulation statics (`definitions.gd:15-21`, `skirmish.gd:33`, `destination_allocation.gd:3`): five recursively frozen named caches (`_unit_cache`, `_building_cache`, `_profile_cache`, `radius_cache`, `reach_cache`); `_extra`, a test registry, and `air_kinds`, a derived lookup rebuilt on reset (neither in `_named_caches()`); `_skirmish_map`, whose outer dictionary is frozen (`skirmish.gd:68-80`); `last_cells_examined`, a shared diagnostic reset and incremented during allocation, read by a test ceiling (`test_allocation.gd:54`). `GridNavigation._snapshot_cache` is per instance. Test resets (`clear_test_kinds` and the like) never run while a worker is active. Task 1 lists every static var and its write sites; a production write to shared static or cache storage after warm-up, other than that diagnostic, is a stop. Worker-owned simulation state, unhashed bot memory, recorder-local commands and instance diagnostics are not that.

## Thread lifecycle

`Thread.wait_to_finish()` has no timeout **[probed]**, so every bounded wait is a poll on main: a deadline from `Time.get_ticks_msec()`, `try_wait()` or a flag read under the lock, and `OS.delay_usec(200)` between reads. A join happens only after the worker has acknowledged its exit.

| State | Who signals quit | Who wakes it | Who sees the exit | Who keeps its objects | Who joins |
|---|---|---|---|---|---|
| idle, asleep on the work semaphore | `stop()` sets quit under the lock | `stop()` posts the work semaphore once | the worker sets `_exited` under the lock as its last act; `stop()` polls it | the pump's self-reference (below) | `stop()`, right after it sees `_exited` |
| healthy, inside a job | the same | not needed; the worker re-checks quit after the job | the same, after it publishes that one job | the same | the same, within `WAIT_MSEC` |
| exited (loop returned or thread died) | n/a | n/a | `drain` reads `not _thread.is_alive()` while unpublished > 0 → `dead thread` failure; `stop()` sees `_exited` or a dead thread at once | the same | `stop()` joins at once (the thread has finished) |
| alive after a stall | `stop()` or the stall check sets quit | `stop()` posts the semaphore (harmless) | nobody: no acknowledgement arrives | the abandoned list, until the process exits | nobody, ever |

**Self-reference [probed]:** a `Thread`'s `Callable` does not keep a `RefCounted` owner alive. In the probe, dropping the last reference freed the object while its thread ran, and Godot printed "Could not call function on previously freed instance" and "A Thread object is being destroyed without its completion having been realized". So the pump keeps `_keep_alive = self` from spawn until a successful join, when it clears it. A failed pump moves into the abandoned list instead.

**Lifetime of a failed pump [proposed]:** every main-side stall (found by `drain`, `query`, `stop` or the start handshake, whose cause is `stall: worker did not start`) goes through one helper, `_abandon(cause)`: set quit under the lock, post the work semaphore, set the first failure reason, set the process latch, clear `_keep_alive`, append to `_abandoned`. On an abandoned pump `stop()` returns at once, `query` returns null and `record()` uses its fallback at once. `static var _abandoned: Array[SimPump]` holds every pump whose thread may still run. It keeps the pump, its `Thread`, simulation, recorder and notes alive until the process exits. Nothing reads them again; `record()` on such a pump uses only main-side copies (the last drained slot, `failure()`). The process latch makes every later pump inline. Each new pump's `start()` joins any abandoned pump whose `_exited` is set (no wait, the thread has finished) and drops it from the list. A thread still running at process exit prints Godot's "Thread object is being destroyed" line, so the fault harness judges each case by its marker and exit status only, never by the absence of error lines. An abandoned thread at process exit exited cleanly on Linux in the critique's probe (5 of 5); on Windows and macOS this is unknown **[probe: macOS in Task 6 (the run is on the Mac); Linux and Windows through the CI `FAULTS` step that Task 9 adds, read at the gate]**.

**Screen exit [proposed]:** `match_screen._exit_tree` calls `driver.stop()` after `orders._set_attack_move(false)` (the spec's "`_exit_tree` calls `stop()`"; today it drops the mouse pan, disarms attack-move, detaches and releases `ViewCaps`, `match_screen.gd:163-167`, and all of that stays). `stop()` is idempotent (Pump hardening), so `close_match` followed by `_exit_tree` is safe.

## Failure channel

- **Causes and who decides:** the worker never writes `_failure`. It queues a marker (`cause`, `tick`) or sets a note flag under the lock: null result, `owner thread`, `fault` (logger count rose during the job). Main turns the first marker it sees, in `drain`, `post` or `query`, into the first failure reason. Main itself detects `stall` (frames, or a query or stop deadline) and `dead thread`. A full queue and an ordinary stop keep `failure()` empty **[owner, 2026-11-18, inherits list]**.
- **After a marker:** in the same critical section that queues its marker, the worker drops the waiting jobs, subtracts them and the failed job from the unpublished count (which is then 0), sets `_exited` and returns. `drain` drops every note after the marker and keeps the slots, so no state from an untrusted simulation reaches the screen. **Count rule, one place:** `post` adds 1; a publish or a marker subtracts its own job; `stop()` and the first marker subtract the waiting jobs they drop; so the count never goes below 0. Once `_failure` is set, `busy()` returns false and `has_room()` returns true, read before the count (a failed pump's `post` still refuses). `record()`'s fallback reads `_recorder` only after `_exited` was seen; otherwise it returns the empty log.
- **Callers:** offline `drain` calls `_read_failure()` right after `pump.drain()`, before its empty-notes return (`offline_driver.gd:77`), because a stall produces no note (freeze card). Online `drain` reads `pump.failure()`; on a new reason it ends the lockstep (`set_protocol_error("sim pump failed: " + reason)`, unless an earlier end stands: Capacity step 1, precedence) and closes the transport in the same frame. The online driver gains `failure()` (passthrough). Online `start()` on a null query result ends with a protocol error before any packet is sent. `_report()` on a null query writes an empty ring. When `driver.failure()` first turns non-empty, the screen clears once, and only when `frozen()` (offline: the freeze card shows and `takes_orders()` is false, so P2.3b's start re-select does not re-arm): first `orders._clear_placement()` while a kind is armed (ghost cells and standing request), then `orders.reset()` (selection, pending build); `reset()` first would empty the kind that `_show`'s ghost cleanup checks. Online it does not reset: the selection stays as the player left it, as at the existing online ends (desync, relay lost, opponent left); a reset would re-select the start builder at the next eligible refresh, because `takes_orders()` omits `driver.over()`. After an online end `_unhandled_input` still reaches `orders.handle` (`match_screen.gd:514-523`) and `Lockstep.submit` can still queue, but `finish_tick` sends nothing (`net/lockstep.gd:66-77,160-161`), and `_show` clears placement every refresh while `input_over()` (`match_screen.gd:536-547`); a universal end-input policy stays outside SB5a **[owner, 2026-11-22; Owner answers 8]**.
- **`query` interrupted:** if the queried job's reply is a marker, `query` returns null and the reason is already set by main. The three production callers are covered: online startup digest (`start`), final command log (`record`), desync ring (`_report`); offline `flush` is test-only and already handles null (`offline_driver.gd:101-113`).
- **Logger [proposed; attribution probed]:** `PumpLogger extends Logger`, installed once per process in debug builds (`OS.is_debug_build()`) on the main thread before the first `Thread.start`, and never removed (Godot's logger list has no lock). `_log_error` takes the logger's own mutex, increments a count for `OS.get_thread_caller_id()` (error types only, not warnings), unlocks, and calls nothing that logs, so it cannot recurse. `_log_message` does nothing (the drivers' `printerr` lines arrive there and are not faults). The worker reads its own count before and after each job. **Probed:** a `push_error` and a script error on a worker thread arrive with the worker's id (two errors), and a main-thread `push_error` arrives with the main id (one), so a main-thread error during a worker job does not fault it. A release build detects no script fault: online, the 30-tick digest is the backstop; offline there is none. **Blind spot:** with `Engine.print_error_messages = false` no custom logger is called (Godot 4.7.2 `error_macros.cpp:109-126`), and `test_relay_transport.gd` turns it off three times (`:85-89`, `:98-100`, `:106-108`); a worker error in that window is not counted. Fault cases assert it is on; Task 1 lists every place that turns it off.
- **Latch on every cause:** main's one first-failure setter sets the process latch for every cause, including a failure from `failing_pump.gd` (as the freeze-card case does, `test_skirmish_scene.gd:1882`), so the next pump is inline (spec: "no pump failed in this process"; fault case `next_match_inline`).
- **Unchanged checks:** null result (Pump hardening), owner thread, stall, dead thread each keep their own cause string and their own fault case.

## Review Focus

1. **Lock scope:** the lock is held only to append or take a job, to publish (note, READY, count) and to drain. `run_job` never runs under it. Task 8's gated-publish case fails deterministically if `drain` skips the lock.
2. **Nothing read across threads without the lock:** the unpublished count, markers, READY, `_exited`, quit. `_failure` and the latch are main-only.
3. **`live()`** asserts in debug builds only. Release builds rely on the owner-thread check in `_run_owned`.
4. **Room before `take`:** a consumed tick can never be posted again, so the check comes first. A refusal after a successful check can only come from a terminal failure (Capacity, step 2).
5. **Two drains in one frame:** the second returns nothing and keeps the slots, in both modes.
6. **Quit re-check after each job** (inherits list) is observable: `stop()` with one running and two waiting jobs ends with the waiting jobs never run (`test_sb5a_stop_with_job_in_flight`).
