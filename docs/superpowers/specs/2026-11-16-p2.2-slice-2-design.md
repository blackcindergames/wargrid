# Quick rematch, slice 2: design (P2.2)

Status: approved by the user 2026-11-16. Decisions marked (user, 2026-11-16) were answered in this session's questionnaire rounds; the agent's calls are listed at the end. Scope lives in the [P2.2 row](../../packages.md#day-lane) and [F27](../../STATUS.md#findings-list); slice 1 is the [slice 1 design](2026-11-15-p2.2-quick-rematch-design.md), its evidence the [verification file](../../reference/p2.2-verification.md).

## Why

Slice 1 gave two friends a rematch from one link, with a minimal result panel. The panel still says nothing about how the match went, a player whose opponent leaves mid-match gets only "Player N disconnected" in the status line (F27), and the launcher has keyboard and target gaps the look-and-feel second pass named ([design answers](../../reference/design-answers-2026-11-08.md#visual-and-ux-proposal-second-pass-user-2026-11-15)). P2.2 goes to production with this slice.

## Goals

- **Result panel statistics**, online and offline, in the B look (buttons centred, user 2026-11-15): outcome, match length, and one row per player (user, 2026-11-16) with units built, units lost and buildings lost. Buttons stay **Play again** / **Back to menu** (renamed from "Change setup" after the slice-1 playtest, user 2026-11-15); Enter is Play again while it is enabled.
- **Opponent left (F27):** on `ended_left` after the start, the panel shows **Victory** with status "Your opponent left" (user, 2026-11-16), the stats up to the leave, Back to menu, no Play again.
- **Leave confirmation online:** "Leave the match? Your opponent wins and the room closes." (user, 2026-11-16). Offline keeps today's behaviour (`offline_driver.confirm_leave()` is false).
- **Launcher riders:** each page's primary button has default focus, so Enter starts the page's action even after focus left the code field (the slice-1 playtest note); a keyboard focus outline that differs from hover, picked in an A/B (user, 2026-11-16); click targets at least 32 px; the Tag at 12 px; Quit in the sidebar on desktop, no confirmation (user, 2026-11-16); the desktop invite field labelled "Match code" unless a web address is configured.
- **Netplay scenario** where seat 2 leaves at tick N and seat 1 ends on the opponent-left panel state.
- **Production release** after the slice-2 playtest on the test app (user, 2026-11-16).

Already done in slice 1 and not redone: Enter in the join-code field joins; elapsed time and Cancel while connecting with no half-open relay session (L20, verification 2026-11-15).

## Non-goals

- Protocol pings (gated rider), F20, F22, anything P2.3 or later.
- Units destroyed, buildings built, credits, army value, graphs, the result-panel tip (a later experiment).
- Play on after a leave (its own package between P2.3a and P7).

## Anti-goals

- No trace re-pin and no change to command formats, replays or the state digest.
- No presentation-side counting: two clients and a replay must show the same numbers.
- No amber used as decoration (amber means "act here", at most one amber button per screen), unless the A/B picks the amber outline knowingly.

## Approaches (count source)

1. **Simulation counters outside the snapshot and hash (chosen, user 2026-11-16).** The simulation increments per-player counters where units are produced and where objects are removed; a new read `match_stats()` returns them. Not in `snapshot()`, so `StateHash.digest` and every trace stay unchanged. Every reference engine counts this way: Zero Hour's `ScoreKeeper` (`Player.cpp:1597`, `ScoreKeeper::crc` empty, `~/projects/CnC_Generals_Zero_Hour` @ `0a05454`), OpenRA's `PlayerStatistics` (not `ISync`, `~/projects/OpenRA` @ `b4d95a5671`), Recoil's `CTeam` counters (not checksummed, `~/projects/RecoilEngine` @ `a0240a9b5c`), 0 A.D.'s `StatisticsTracker` (full hash only every 20 turns, `~/projects/0ad` @ `136720dada`). Research by an Opus agent, 2026-11-16. This replaces "tallied by the drawing side, no simulation change" (user, 2026-11-15).
2. **Drawing-side tally.** Rejected: death events carry only `object_id` and are cleared each tick, and the screen steps many ticks per frame during catch-up, so counts can drift between clients.
3. **Counters in the hashed snapshot.** Rejected: `StateHash.digest` hashes the whole snapshot, so every recorded trace would need a re-pin for display-only numbers.

The cost of 1: a counting bug cannot desync a match, but two clients could show different numbers. A test replays one match and compares `match_stats()` at the end; a mirror test compares the two seats.

## Design

### Simulation (`game/scripts/simulation/`)

- Per player: `units_built`, `units_lost`, `buildings_lost` (ints), created with the player, kept beside `_players`, not inside the player dictionary (which `snapshot()` copies).
- **Units built** (user, 2026-11-16): a unit produced from a building's production queue (`production.gd`, the queue path that calls `spawn_unit`). Start units, crate spawns, rebuild-hole workers and free units from `spawns_on_complete` do not count (Zero Hour: "built from a building"; free units are the agent's call, below).
- **Units lost:** a unit of that player that dies: the `death` event paths in `combat.gd` and `containers.gd`, plus units buried with the last tunnel or their container (`Containers._bury`, plain `remove_object` without a death event; counted as lost, agent's call). Not a hook in `remove_object`: it also serves cancel (`construction.gd`), hole-worker cleanup (`rebuild_holes.gd`) and supply sources, which are not losses.
- **Buildings lost** (user, 2026-11-16): a completed building of that player destroyed; unfinished sites and rebuild holes do not count. A hole is created with `completed: true` and removed when its site completes, so the rule tests for the hole marker, not only `completed`.
- Count a unit as built only when `spawn_unit` returned a valid id (it returns -1 when exits are blocked).
- **Match length:** `tick()` divided by the tick rate, shown as m:ss (user, 2026-11-16); game time, the same on both seats.
- `match_stats() -> Array[Dictionary]`: one row per player in id order, `{player, units_built, units_lost, buildings_lost}`, copies. Documented in [sim interface](../../reference/sim-interface.md) under "State out" with the note "not in the snapshot, never hashed: display only"; the [determinism rules](../../reference/determinism-rules.md) gain the same exception beside bot memory.

### Result panel (`game/scripts/match/result_panel.gd`)

- B look: card centred over the dimmed world, title (Victory, Defeat, Draw), status row, the length line, a small table with column headers Units built, Units lost, Buildings lost (one row per player: seat and faction, then the three numbers; the local row marked "(you)" and bold, never by hue alone), two centred buttons. When Play again is disabled (friend left, room closed, opponent left), Back to menu takes focus so Enter activates it. Layout values follow slice 1's card padding and the 12 px floor.
- `show_result` gains the stats rows and the length; the panel stays a pure view and reads nothing from the simulation itself (`match_screen` passes `driver.sim.match_stats()` and `tick()` on end).
- The panel is fed by `hud._match_hud` (`show_result(result, driver.rematch_line(), driver.can_play_again())` on every refresh); the stats and length join that call.
- Opponent left: one rule, `Lockstep.opponent_left()` (agent's name): status `ended_left`, not `left_before_start()`, and the room had two seats. The online driver and `headless_client` both call it, so the netplay scenario runs the real rule; the hud's panel route is covered by a unit test. When true the panel shows title Victory, status "Your opponent left", `can_play` false. A leave after a normal end keeps slice 1's "Your friend left". With more than two seats the rule is false and today's notice stays, until the Play on after a leave package (its 1v1 case keeps this panel). `left_before_start()` keeps today's notice; desync, relay lost and protocol ends keep theirs.

### Leave confirmation (`game/scripts/presentation/pause_menu.gd`)

Online confirmation text as above, and Cancel takes the default focus instead of Leave (`pause_menu.gd` focuses Leave today), so a stray Enter does not forfeit. Offline unchanged.

### Launcher (`game/scripts/launcher.gd`, `game/scenes/launcher.tscn`)

- Default focus: `show_page` focuses the page's primary button (Play: Start or Create, whichever the opponent toggle shows, refocused when the toggle changes; Join: the code field if empty, else Join; Waiting: Copy); Enter on a focused option button keeps Godot's open behaviour, so the plan checks Enter after a faction pick returns focus to the primary button.
- Focus outline A/B (user, 2026-11-16): three variants (2 px off-white outline, 2 px amber outline, inset bar), hover stays a background tint; offscreen captures of the Play page with one button focused and one hovered per variant on an A/B page opened in Firefox; a stop gate for the user's pick before the chosen style is applied to every launcher button.
- Click targets at least 32 px high; Tag font 12 px.
- Quit: a sidebar button below Credits, desktop only (`OS.has_feature("web")` hides it), calls `get_tree().quit()`; locked by `_set_busy` like the nav buttons, so a host cannot quit out of a connecting or waiting room by accident.
- Invite field label "Match code" and its copy button "Copy code" when no web address is configured (today's `page` check at `launcher.gd` `_copy_text`), "Invite link" / "Copy link" otherwise.

### Netplay (`tools/run_netplay.sh`, `game/scripts/net/headless_client.gd`)

New scenario `left-mid`: seat 2 sends `leave` after tick N (N well past the start); seat 1 prints the end state; the scenario passes when seat 1's `Lockstep.opponent_left()` is true (printed as `VICTORY left`), and fails on `left_before_start`.

### Playtest

One focus card "Result panel" (user, 2026-11-16): stats readable at a glance, opponent-left panel, leave text. Launcher riders checked as a list, not scored. Test-app deploy of relay and web, then production relay and web after the playtest; each deploy needs the user's approval.

## Agent calls not asked

- Free units from `spawns_on_complete` (for example a free collector with a supply building) do not count as built: they were not ordered. Zero Hour's rule for free units was not checked.
- Counters live beside `_players`, not in the player dictionary, so `snapshot()` and `view_state()` stay unchanged.
- The stats table shows every player in seat order, the local player marked; bot players show as their faction.
- Waiting page default focus is Copy; Join page focuses the code field only while it is empty.
- Wording of the length line ("Match length 12:34").
- Buried units count as lost; cancel and hole cleanup do not.
- Opponent-left rule lives in `Lockstep` so headless and game share it; two-seat rooms only.
- Mid-match leave reads "Your opponent left", a leave after the end keeps "Your friend left".
- From the player-experience review: Play-page focus follows the opponent toggle; leave confirmation focuses Cancel; Back to menu takes focus when Play again is disabled; table headers and a "(you)" marker; Quit locked while busy.
