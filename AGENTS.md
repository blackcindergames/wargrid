# Project instructions

## Intent and scope

Wargrid is a Godot isometric RTS with geometric 2.5D art, inspired by Zero Hour's game design. Preserve strategic identity and feel; original bugs and slow algorithms are not compatibility requirements. The goal is Wargrid's own game that feels very close to it, not mathematical parity; see [Zero Hour verification](docs/reference/zero-hour-verification.md).

Current setup lives in the [development notes](docs/development.md); package state and what waits for the owner only in [`docs/STATUS.md`](docs/STATUS.md), which other documents link to and never repeat; `README.md` is the player-facing page. Milestone scope lives in [the blueprint](docs/blueprint.md); see its §7 and the long-term 3v3 target. Remaining acceptance evidence lives in the development notes. Implement only the explicitly requested milestone and stop at its exit gate; do not automatically expand into later milestones, factions or multiplayer. Writing, editing or approving a plan, or preparing a branch, never starts implementation on its own.

## How a package runs

1. **One page first:** what the player will notice, the observation that would refute it, the first playable slice, what is out. Look for the refuting observation in data that already exists before running anything new.
2. **Player-facing packages** build the smallest playable slice first, test-first for simulation rules; then the owner plays it for ten minutes. Measuring and polishing come after that match and aim at what it showed. Other packages name a headless check on their one page as first evidence.
3. **Harden once, at the end:** pins and traces, one fresh Opus review of the whole branch, the benchmark row, one status line, the guide chapter. Diffs in the simulation, netplay, `relay/` or `protocol/` also get a review per task. A branch that touches those areas, or changes more than about 500 lines, also gets Gemini 4 Neon (high) through `agy` as a second gate reviewer; skip it and say so when `agy` is missing or out of quota (user, 2026-11-22, after the reviewer benchmark, private).
4. **Builders run on Sonnet;** UI, HUD, mock-up and art builders on Opus.
5. **Night runs** take work whose result a headless check, offscreen screenshots or a War Room round can show; work that needs a match to judge waits for the day.

## Implementation

- Terminal-first: author, import and test through files and documented commands; no routine editor clicking.
- Keep Godot project under `game/`, repository tools outside it. `res://` resolves to `game/`. Follow the active milestone execution plan for exact paths and contracts.
- Use typed GDScript. Keep authoritative simulation separate from scenes, rendering, wall-clock time and networking callbacks. Advance it explicitly by ticks; inject randomness when needed.
- Simulation code follows the [determinism rules](docs/reference/determinism-rules.md).
- Adapt Hell's Verdict's wrappers and CI patterns without modifying that project. Keep Wargrid's planned renderer and tick rate; do not inherit FPS settings or server assumptions.
- Follow personal code-style, Superpowers, review and model-routing instructions. Do not import another project's agent models or workflow exceptions.
- Design specs, plans, playtest cards, mock-ups and diffs touching UI, HUD, controls, art or player-facing text also get the [player-experience reviewer](.claude/agents/player-experience-reviewer.md), beside the correctness reviewer, not instead of it; not on simulation, relay or tooling-only diffs (user, 2026-11-16). It runs unasked, in planned work, ultracode runs and ad-hoc edits alike, before the work is reported done or shown to the user; typo, rename and comment-only diffs are exempt; a workflow stage that cannot call an agent by name gives a general agent the file to read and follow (user, 2026-11-19). The [game director](.claude/agents/game-director.md) runs only when the user asks for it, usually through `/director`, and never starts a package (user, 2026-11-19).
- Attended packages follow [How a package runs](#how-a-package-runs). Unattended runs follow [night run](docs/night-run.md); the [milestone prompt](docs/milestone-prompt.md)'s stop conditions apply to both.
- New tests use only the [simulation interface](docs/reference/sim-interface.md); `tools/test_sim_boundary.py` enforces it.
- Edit files with the Edit tool or asserted replacements only; an unasserted replacement once dropped a cleanup call silently. Scratch Godot scripts must `quit()` on every path, or a script error hangs until the shell timeout.

## Verification and desktop use

- After a merge to `main`, follow [After a merge](docs/development.md#after-a-merge) (benchmark on `main`, ceiling alarms, owed rendered reruns, generated tables).
- Test output (Wargrid override of the global delegate-to-subagent rule): redirect suite and benchmark output to a file and read only the summary lines; on failure read only the failing lines. Use subagents for reviews, not for running tests.
- A new command gets same-tick tests against every existing command and against removal, and every AI rule a spec-worded test; plans need not list them. Benchmarks assert that their mechanics run inside the timed window. HUD changes get a headless layout test. Report every check with the tree it ran on.
- Before reporting GDScript changes done, `sh tools/run_lint.sh` and `sh tools/run_warnings.sh` pass (new code is typed; tests are exempt from `untyped_declaration` only) (`sh tools/run_checks.sh` runs lint, warnings, Python, shell and public checks at once).
- Before reporting Python tooling changes done, `sh tools/run_python_checks.sh` passes (config in `tools/pyproject.toml`).
- Before reporting shell script changes done, `sh tools/run_shell_checks.sh` passes (ShellCheck on every tracked `*.sh`; config in `.shellcheckrc`).
- Write meaningful behavior tests alongside mechanics. Keep small suites per system; fail on zero checks, parse errors, failed expectations and incomplete suites. Require successful exit plus final completion marker.
- Rendered benchmarks (`sh tools/run_game.sh res://scenes/movement_benchmark.tscn`) open a window: ask first, batch with other visible checks. They disable vsync themselves (header shows `vsync=off`) so frame intervals measure render cost, not display refresh.
- Pass `timeout: 600000` on every suite, benchmark, netplay, lint and parity call (the suite takes about 78 s; the default 120 s fired 57 times in two days); details in [milestone prompt](docs/milestone-prompt.md).
- Run commands before claiming they work. Report counts, exit status, unverified checks and reference gaps.
- While iterating, `WARGRID_TEST_ONLY=<suite file or case name substring> sh tools/run_tests.sh` runs just the cases whose suite file or case name contains that text (plain substring, so `test_` matches everything; seconds, one process); the full suite is still the gate before reporting done.
- Wait on long jobs with `run_in_background` or a Monitor until-loop, not `sleep`/`pgrep` polling (873 min of session time went to polls in one week); wait on CI with `gh run watch --exit-status`.
- Keep tests, replays and simulation benchmarks headless. Open a visible game window only when the user asks to play. Ask before visible windows and other rendering-dependent checks; batch such checks into one request. Exception (user, 2026-11-14): a UI round may take one batch of offscreen screenshots per screen (rendered to files, no visible window, no sound) and have a reviewer compare them with the mock-ups before the user's look.
- Separate internal correctness from reference fidelity. Record intentional fixes with regression tests; never silently widen tolerances or change expected results to hide failures.
- In any milestone, a mechanic Zero Hour also has can be measured with the [parity harness](docs/reference/zero-hour-parity-harness.md) (headless, silent, source build). Results are evidence for a decision list, never an automatic number change.
- For documentation-only changes, check links, paths, status labels and consistency. Automated tests do not establish game feel or measured performance.

## Reference handling and Git

- Reference engines for behaviour and algorithms, read-only, cite path:line with the revision: Zero Hour (`~/projects/CnC_Generals_Zero_Hour`, fork `~/projects/GeneralsGameCode`) for game behaviour and values; the others by topic, most cited first, all under `~/projects/`. Simulation, pathing and crowds: `0ad`, `RecoilEngine`, `warzone2100`, `OpenRA`, `permafrost-engine` (evaluation outside the repo: `~/projects/wargrid-overnight-work/engines/permafrost-engine.md`). Lockstep, netplay and relay: `OpenRA`, `RecoilEngine`, `0ad`, `warzone2100`, `OpenTTD`, `OpenRCT2`, `ioq3`, `Hypersomnia`. Bots: `Zero-K`, `0ad`, `PurpleWave`, `warzone2100`. HUD and player experience: `Beyond-All-Reason`, `Zero-K`. Read the earlier findings before sweeping the engines again: [simulation review](docs/reference/simulation-reference-review.md), [netplay review](docs/reference/netplay-reference-review.md), [fair bots research](docs/reference/fair-bots-research.md). The porting rule below covers the sources it names; check the licence of any other project before porting from it.
- Query Zero Hour INI data through `python3 tools/zh_ini.py dump` and the local `build/zh_ini/inizh.jsonl` (cite entry:line), never a hand-rolled decoder; the dump is never committed.
- Need a Zero Hour model size (unit footprint, mesh box, bone position)? Run `python3 tools/zh_w3d.py dump` and query `build/zh_w3d/w3d.jsonl` (usage: [testing and tooling guide](docs/guide/13-testing-and-tooling.md)); never decode W3D by hand. Sizes only; never commit the dump or any model bytes.
- Keep EA source and installation backups outside this repository and unchanged. Record source revision or archive hash, internal path and uncertainty for findings. Read the source to learn behaviour, values and ideas for a game inspired by it, then write Wargrid's own code: Zero Hour is full of bugs and slow paths. Wargrid is GPL-3.0-or-later (`LICENSE`), so porting GPL code (EA source, OpenRA, GeneralsGameCode, Permafrost Engine) is legally allowed but the exception: only a small algorithm where our own version would be clearly worse, rewritten in typed GDScript, with a comment naming source repo, revision and path; ported EA code keeps EA's copyright line and a pointer to EA's additional terms. No bulk translation. Never copy EA assets, INI/map data, art, audio, text or trademarks into Wargrid. Exception (user, 2026-11-05): maps from EA's GPL-released `CnC_Modding_Support` may be converted by a repo tool into Wargrid map data; the output keeps EA's copyright line, a pointer to EA's additional terms and the source revision, and uses Wargrid's own map name.
- M0 and future ordinary CI must work without sibling projects or retail game data.
- Preserve user changes. Keep caches, build output, local environment files and temporary analysis out of tracked source.
- The repository is public; tracked files are engineering records (user, 2026-11-12). Working files (handoffs, session notes, raw prompts, pasted chat) go to the private notes repository. State decisions and findings as reported statements with a "(user, DATE)" tag; quote the user only where the exact wording is the evidence (a playtest report, an approval). No personal detail: other load on the machine is "host under load", playtesters stay unnamed, hosting notes give costs but not whose account or registrar. Paths are home-relative (`~/projects/…`); no hostnames, LAN addresses, full session ids or agent scratch paths. `sh tools/check_public.sh` checks the mechanical part in CI and at wrap-up; fix a hit by rewording, never by weakening the check.
- Merge a branch into `main` with `git merge --squash` as one to three commits per package; first tag its tip `<branch>-tip` with a message (`git tag -m "<branch> branch tip" <branch>-tip <sha>`: tags here are signed, so a bare `git tag` fails with "no tag message?") and push the tag with `main`, so hashes cited in verification files stay reachable (user, 2026-11-18).
- Wargrid override of the global commit rule: do not commit, push, open a PR, merge or deploy to fly without explicit approval, except local commits pre-authorized by the [milestone prompt](docs/milestone-prompt.md) during a milestone run, or by the [night run](docs/night-run.md) preparation and handoff.
